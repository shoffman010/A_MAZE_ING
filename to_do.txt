A-Maze-ing checklist
====================

Mandatory items to complete
---------------------------
[ ] Handle every user-facing error without a traceback.
    - Catch the "maze too small for the 42 pattern" error raised when Menu.run()
      creates a Maze.
    - Catch file-writing errors when saving the generated maze.
    - Keep error messages clear and return cleanly to the user.

[ ] Preserve mandatory seed support and fix omitted-SEED parsing.
    - The subject requires reproducible generation when a seed is provided.
    - SEED is not listed among the mandatory configuration keys, so a config
      without it must still work and use seed=None.
    - config.py currently indexes SEED directly; use a default empty value when
      the key is absent, while rejecting non-integer seed values.

[ ] Make the project pass the required lint command.
    - Run make install, then make lint.
    - Fix flake8 issues (including long lines and unused imports).
    - Fix mypy issues, including the missing -> None annotation on Maze.__init__
      and the incorrect str annotation for MazeWriter.write_maze(path).

[ ] Improve the clean target in the Makefile.
    - Remove __pycache__, .mypy_cache, and any other generated cache directories.

[ ] Add README.md at the repository root.
    - First line: italicized text stating that this was created for the 42
      curriculum by the team login(s).
    - Add Description, Instructions, and Resources sections.
    - Document the complete config-file format, the recursive-backtracker
      algorithm, why it was chosen, reusable code, team/project management,
      references, and how AI was used.
    - Include generator usage: instantiate it, use custom size/seed settings,
      access the maze structure, and retrieve a solution.

[ ] Package the reusable generator as required by Chapter VI.
    - Add the source/build configuration needed to build a pip-installable
      mazegen-* package from a clean environment.
    - Build and keep a mazegen-*.whl or mazegen-*.tar.gz at the repository root.
    - Ensure the reusable module and its documentation are available in the
      package as a single installable unit.

[ ] Ensure the mandatory visual pattern is always "42".
    - Either remove X/Box as selectable patterns or clearly make them optional
      bonus behavior while the default/required path always renders 42.

[ ] Re-run end-to-end checks.
    - Valid perfect maze: output validates and has one entry-to-exit path.
    - Valid imperfect maze: output validates and has a shortest path.
    - Invalid syntax, missing file, missing optional SEED, too-small dimensions,
      invalid markers, and unwritable output all show friendly errors.

Bonus options from the subject
------------------------------
[ ] Support multiple maze-generation algorithms.
    Examples: Prim's algorithm or Kruskal's algorithm alongside recursive
    backtracking; expose the choice through an optional config key.

[ ] Animate maze generation.
    Redraw the terminal maze as cells/passages are carved, with a small delay or
    a configurable animation speed.

Optional polish ideas
---------------------
[ ] Add automated tests (pytest or unittest) for parsing, wall coherence,
    reproducible seeds, path validity, and output serialization.
[ ] Add a config option for display mode or animation speed.
[ ] Keep alternate protected patterns only as an explicitly documented extension.
